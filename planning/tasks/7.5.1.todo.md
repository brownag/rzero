# 7.5.1 -- List single-index assign stores the first element

## Goal
Make `l["b"] <- <atomic>` on a list store one length-1 element per selected slot (element `k % len` of the value), matching GNU R's first-element behavior.

## Notes
- Analysis, Rscript (read-only), output:
  ```
  Warning message:
  In l["b"] <- c(1, 2, 3) :
    number of items to replace is not a multiple of replacement length
  List of 2
   $ a: num 1
   $ b: num 1
  ```
  So GNU R stores `1` (length 1) and warns. Warning not reproduced in R0 (R0 has no warnings channel; out of scope).
- Anchors: `elem_at` (src/vm.rs L44) is a 0-based element extractor over Dbl/Int/Lgl/Chr/Range returning a length-1 same-type vector. Only other caller is `for` (L329) and subset path (L824); not modified.
- Arms before `v if !is_df` already consume `Df`, `List`, and `Null`, so the remaining value is always atomic (Dbl/Int/Lgl/Chr/Range). `elem_at` covers all of them; no extra type guard needed.
- `is_df` path (`subset_assign`, `atomic_rhs`) untouched.
- Constraint: R0 has no `NULL` literal; tests use `c()` where needed.
- Risks: `elem_at` panics on index out of range only if `k >= len`; `k % len` with len>0 prevents that. Zero-length guard prevents divide-by-zero.

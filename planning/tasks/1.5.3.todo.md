## Notes
- **Analysis facts.**
  - Stub at `src/vm.rs:548` (`call_intrinsic(&mut self, _func, _args: Vec<(Option<String>, R0Val)>)`). The call site (`Expr::Call`, line 229) already checks user functions first, so user calls are unaffected.
  - The `eval_call` reference (INITIAL_SPEC.md 1978-2235) has no `%in%` arm (its `BinOp::InOp` is rejected at `vm.rs:309`). The plan's 24 names match the reference's arms exactly: c, length, seq_len, seq_along, is.na, which, ifelse, pmin, pmax, abs, sqrt, exp, log, log10, floor, ceiling, sum, mean, min, max, cumsum, diff, approx, data.frame, list. No plan-named name is missing from the reference. `%in%` is added from D17 and is not in the reference.
  - Reference `na.rm` handling is a pre-filter: any `na.rm` arg is stripped and read as TRUE only if it is Lgl TRUE. Replaced here by the binder.
  - The reference `c` and `ifelse` promote everything to Dbl. That is the bug D3/the plan's type rule targets. Replace with common-type code, not `promote_dbl`.
  - The reference `sum` on Lgl maps TRUE to 1.0 and always returns Dbl. D19 changes it to Int.
  - Parser: `Tok::InOp` emits `Expr::Call { func: "%in%" }` (parser.rs:106). Pipe desugar exists (parser.rs:105), so the E9 pipe test can run as written.
  - Helpers available: `promote_dbl`, `materialize_int`, `len`, `na_of_type_like`, `is_na_real`, `na_real`, `NA_INT`, `LGL_*`, `R0Val::df`. No `value.rs` change needed.
  - Existing test `call_intrinsic_still_stubbed` (vm.rs:627) asserts `sum(1)` errors with the stub. It becomes false by design and is deleted here.
- **Constraints honored.** `vm.rs` only. `value.rs`, `ast.rs`, `parser.rs`, `lexer.rs` untouched. No new dependencies. Debug-form compares since `R0Val` has no PartialEq.
- **Scope.** The plan's 24-name list plus `%in%`, with no spec-only intrinsics. Unimplemented names stay `Unknown function`. The implemented list goes into the STATE report.
- **Risks.**
  - About 12 steps; the test step is dense. If it grows, split the tests into their own step rather than adding items.
  - Named-arg order rules are not in the spec (Question 2).
  - Clippy `-D warnings` on the many match arms. Use slices and iterators.
  - `%in%` on Chr is not specified (Question 4).

## Questions
1. **`c()` with Chr.** The plan says common type, but Chr is not named. Proposed: Chr+Chr gives Chr. Chr mixed with a numeric or Lgl gives `TypeError:`. Approve?
2. **Named-arg binding order.** Proposed: exact-name match first, then positional fill of unbound slots in order. Unknown names are `UnknownArgument:`. A named arg that the function does not take is an error for every intrinsic, including `na.rm` on `length`. Approve?
3. **`min`/`max` result type.** D19 covers `sum` and `mean`. Proposed: `min`/`max` of Int input returns Int, of Lgl returns Int, and of Dbl returns Dbl. Alternative: always Dbl, as the reference does. Which?
4. **`%in%` on Chr and mixed types.** Proposed: Chr vs Chr uses string equality (NA matches NA). Chr vs numeric is `TypeError:`. Numeric/Lgl pairs compare via `promote_dbl`. Approve?
5. **`abs`/`floor`/`ceiling` on Int.** The reference returns Dbl. Proposed: keep Dbl for all of them (matches the reference, and no decision covers it). Alternative: Int in, Int out for `abs`. Which?

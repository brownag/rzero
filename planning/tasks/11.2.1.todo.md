## Notes
- Existing harness: `canon_r0` (Rust) vs `canon()` in `tests/gnu_r/canon.R`; `run_rscript_file` sources canon.R, `parse(file=)`s the path, evals each expr in a `new.env()`, prints `canon(last)`. It calls plain `Rscript <file>` (no `--vanilla`); spec requires `--vanilla` for the new test. Rscript is at /usr/bin/Rscript; tests skip when absent.
- `r0_corpus_matches_gnu_r` iterates all `tests/r0/*.R0` and feeds them straight to GNU R; a file with `fn`/`: type`/`->` would fail there (GNU R parse error), so the new file will break that test unless excluded. No existing corpus file uses `fn`, types or `->` (grepped). Plan: skip `g12_*`/R0-only stems in `r0_corpus_matches_gnu_r` (small filter), since both tests live in the same file. Allowlist is not suitable (it expects a mismatch and flags a stale entry on parse failure it would still record as "Rscript failed").
- R0 semantics: `fn` is only legal as `name <- fn(...)` (vm.rs:140, 396); a bare/anonymous `fn` (including inside `list(...)`) errors "Anonymous functions must be bound to an identifier in R0". Assignment of a FnDef yields NULL. `R0Val` has no function variant, so a function can never be the final value or list element.
- 11.1.1 gotchas: `%>%` -> `|>`; `=` inside parens/brackets, `<-` elsewhere (so use `=` only for named args; avoid `=` top-level assignment in the corpus); whole-number doubles print without `.0` (`1:10` stays); type stripping drops exactly one token, so types must be single identifiers (`dbl`, `int`, `df`, etc.); comments dropped.
- Existing typed example for reference: `PEDON_SCRIPT` in conformance.rs:212 (`function(hz: df, z_min: dbl = 0, z_max: dbl = 100) -> dbl`); can mirror its style but reuse of the pedon body needs `approx`, which I will avoid.
- R0 rejects at runtime (Err) are `println!("reject")` in the old test; in the new test an R0 Err must be a failure, not a silent skip (otherwise the test is vacuous).
- Risk: `Rscript --vanilla` on a temp file in `std::env::temp_dir()`; `return(...)` and `if` at top level of function bodies are fine in R. Avoid `else` on a new line after `}` at top level.
- Risk: spec-listed construct "fn inside list(...)" is incompatible with R0 (above).

## Questions

Proposed: include it in a way that is valid in both: define `f <- fn(x: dbl) -> dbl x + 1` normally, and exercise "fn inside list(...)" only as the transpiler unit test (already covered by 11.1.1: `list(f = fn(x: dbl) -> dbl x)`) -- corpus file would not contain it. Alternative: add an extra transpile-only assertion in `r0_transpiled_matches_gnu_r` that `transpile_to_r("list(f = fn(x: dbl) -> dbl x)")` yields text GNU R parses (`parse(text=)`), without evaluating.

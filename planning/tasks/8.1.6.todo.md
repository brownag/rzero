## Notes
- Value asserts migrated: 14.
  - `seq(n)` group: `seq(4)`, `seq(4L)`, `seq(0)`, `seq(c())` (4).
  - `seq(from, to)` group: `seq(2, 5)`, `seq(5, 2)`, `seq(3, 3)` (3).
  - `seq(from, to, by)` group: `seq(1, 5, by = 2)`, `seq(1L, 5L, by = 2L)`, `seq(5, 1, by = -2)` (3).
  - `seq(from, to, length.out)` group: `seq(1, 10, length.out = 4)`, `seq(from = 1, length.out = 3)` (2).
  - `seq(along.with)` group: `seq(along.with = c("a", "b", "c"))`, `seq(along.with = c())` (2).
- Error asserts kept in Rust: 5 (`eval_err(...).contains(...)`: `seq(NA_integer_)`, `seq(1, 5, by = -1)`, `seq(5, 1, by = 1)`, `seq(1, 5, by = 0)`, `seq(1, 5, length.out = -1)`).
- Exclusions applied: none listed for 8.1.6 in the table. No known divergence in H4 touches this function.
- Risks:
  - Range-valued results (`R0Val::Range`) in the Rust asserts become plain vectors in the corpus. Canonicalization must print them the same as GNU R's integer or double vectors. `seq(0)` gives the descending range `1 0` on both sides.
  - `seq(c())` and `seq(along.with = c())` must give an empty integer vector on both sides. GNU R `seq.default` returns `integer()` for a zero-length single argument, so this should match.
  - Doubles from `by =` and `length.out =` are checked by the harness, not by hand.

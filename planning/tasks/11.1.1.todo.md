## Notes
- There is no `Lexer` struct or `lex`; the API is `pub fn tokenize(src) -> Result<Vec<Tok>, String>` (`src/lexer.rs:112`). `Tok` has no spans.
- Lexer facts: `"function" | "fn"` both -> `Tok::Fn` (:239); `->` -> `Tok::Arrow` (:276); `:` -> `Tok::Colon` (:305); `|>` -> `Tok::Pipe` (:279) and `%>%` also -> `Tok::Pipe` (lossy); `<-` and `=` both -> `Tok::Assign` (lossy); comments dropped; significant newlines/`;` -> `Tok::Term`; trailing `Tok::Eof` presumably pushed at end (to confirm in impl).
- Parser reference: param type is `Colon` + one token; return type is `Arrow` + one token after `)` (parser.rs ~237, ~278-281). Mirror that exactly so the type is a single token (`dbl`, `int`, etc.).
- Lexer-induced lossiness the printer must handle: `Tok::DblLit(f64)` (`1` vs `1.0`/`1e3` all become f64; print with Rust `{:?}`-style so integers keep a `.0` or round-trip), `NA_real_`/`NaN`/`Inf` are folded into `DblLit`, `NA_integer_` -> `IntLit(NA_INT)`, `NA_character_` -> `NaChr`, `NA`/`TRUE`/`FALSE` -> `LglLit`. Printer must map these back to R names.
- Lexer suppresses newlines after operators/open delimiters, so emitting `Term` as `\n` is safe; `else` after `}` on a new line can break in GNU R at top level, so print `Term` conservatively (risk, see Q3).
- Hazard: `Tok::Placeholder` (`_`) must be printed as `_`; R 4.2+ accepts it only in pipes (matches R0 use).
- Constraints: pure Rust, no `std::fs`/`std::process`; do not touch vm.rs, parser.rs, main.rs, tests/.

## Questions
1. `Tok::Assign` covers both `<-` and `=`, so a named arg `f(a = 1)` and an assignment `x <- 1` are indistinguishable at the token level. Plan: print `=` when directly inside a call/param paren (stack depth > 0) and `<-` at depth 0 / inside braces. Acceptable?
2. Numeric printing: `DblLit` loses the original text (`1`, `1.0`, `1e3`). Plan: print f64 with `{:?}` (so `1` -> `1.0`, NaN -> `NaN`, NA payload -> `NA_real_`, inf -> `Inf`). Is normalized-but-numerically-equal output OK, including `1:10` becoming `1.0:10.0`? (Alternative: print integral values < 1e15 without the `.0` to keep `1:10` textually intact; I propose this.)
3. Statement separators: emit `Term` as `\n`, accepting that a top-level `if (...) {...}\nelse ...` could mis-parse in GNU R. Lexer already treats `Else` as suppressing newline only after `else`, not before it, so R0 source likely never has a newline before `else` at top level. OK to ignore?
4. `%>%`, `%in%`, `%%`, `%/%`: `%>%` and `|>` share `Tok::Pipe`, so `%>%` would be emitted as `|>`. OK (both are GNU R pipes for the supported forms; `_` placeholder works with native `|>` only in R >= 4.2)?

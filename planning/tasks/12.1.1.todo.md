## Notes
- `R0Val` derives only `Clone, Debug`; there is NO `PartialEq` (vm.rs:3965 comment compares Debug forms). `UserFn` derives `Clone, Debug`, so `Fn` inherits both. PartialEq is not added: `Expr` has no PartialEq-needed use and canonical function comparison is undefined (Decision Log).
- `UserFn` contains `HashMap<String, R0Val>`, so the type is recursive; the HashMap already provides indirection, but `Box` keeps `R0Val` small (params + `Expr` inline would bloat every value).
- Dry run in a scratchpad copy (repo untouched): adding the variant and the visibility change yields exactly 3 non-exhaustive errors, all in `src/value.rs` (lines 135, 145, 230). Rustc may reveal more in `src/vm.rs` only if they are not hidden behind these; most vm.rs matches use wildcards. Expected total: 3, at most a few more.
- Spec says payload `UserFnValue`; I use `Box<UserFn>` directly as the smallest payload (no wrapper type). Later tasks only need `R0Val::Fn(Box<UserFn>)`.
- Constraint: only `src/value.rs` and `src/vm.rs` are touched.
- Risk: later tasks (12.2.x) pattern-match `Fn(UserFnValue)` per spec text; the name differs. Orchestrator should confirm `Box<UserFn>` is acceptable.

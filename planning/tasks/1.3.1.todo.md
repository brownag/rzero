## Notes
- Repo state: `master`, clean tree (apart from this planning file). `src/lexer.rs` holds only `//! Tokenizer for the R subset.`. `src/value.rs` (1.2.1, committed) exports everything the lexer needs; `Lgl` is `u8`, `NA_INT` is `i32::MIN`.
- Spec alignment (EXECUTION_PLAN_1 1.3.1, D3, D17, E12):
  - `%in%` maps to `Tok::InOp` as in the prototype. The parser (1.4.1) owns the desugaring to the intrinsic. The lexer does not change.
  - E7 (`Copy` on `BinOp`) does not apply here. `Tok` derives `Clone, Debug, PartialEq`, not `Copy`, because `StrLit`/`Ident` hold `String`.
  - D4: `std` is available; no `no_std` concerns.
- Constraints honored: only `src/lexer.rs` is edited. `tokenize` returns `Result<Vec<Tok>, String>`. Error texts are copied verbatim, not reworded.
- Prototype bugs found in Analysis (ported unchanged per "keep the rules exactly", listed as Questions):
  1. `]]` is always one `RBrack2` token and decrements depth by one. Nested indexing such as `a[b[1]]` tokenizes as `LBrack, Ident, LBrack, DblLit, RBrack2`, which the parser cannot match. Correct fix needs a bracket stack.
  2. A newline after `)` emits `Term`. So `function(x)\n{ ... }` and `if (c)\n x` break at the newline. R accepts both.
  3. The "Unexpected character" arm formats `c = bytes[i] as char`. For a non-ASCII byte this shows a Latin-1 mojibake character, not the real one. The error is still deterministic.
  4. `;` always pushes `Term`, even right after another `Term`. Harmless for the parser if it skips empty statements; unverified.
  5. `1.5L` is not an int literal (`is_float` blocks the `L` suffix). It lexes as `DblLit` followed by `Ident("L")`.
- Clippy risk: `tokens.last().map_or(true, ...)` may trigger `clippy::unnecessary_map_or` on newer toolchains, which fails `-D warnings`. Fix choice is Question 4.
- Risks: a wrong `suppresses_newline` list changes parse results without a compile error. The three acceptance tests and the keyword test cover the main paths. Parser-level tests (1.4.1) will catch the rest.

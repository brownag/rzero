## Notes
- Only file in scope: `tests/conformance.rs`. No `src/` edits. A failure caused by a `src/` bug: STOP and report. Do not change expected values. A second identical failure on the same test: STOP.
- Expected values re-verified this session by running `cargo run --release`: `wt_clay_0_100cm` = 25.666; `interp_25_50_85` = 21.7381 29.0526 28.7059; `remaining_oob` = 14.5 NA NA; fuel remaining 99809. These match D13 and E6.
- Script source: `src/main.rs` already uses the E5 form (`sum(valid_thick * hz$clay[valid]) / total_thick`). The E5 trap (`|> sum() / total_thick`) exists only in the INITIAL_SPEC.md copy at lines ~2256, which is not used here.
- `$` on a list: parser `Tok::Dollar` builds `Expr::Field` (parser.rs:85). VM `field()` (vm.rs:470) handles both `R0Val::Df` and `R0Val::List` by name. So `$` on the list returns the named column, as the plan assumes.
- `R0Val::List { names: Vec<String>, cols: Vec<R0Val> }` (value.rs:95). `R0Val` has no PartialEq, so comparisons use `match`, `f64` tolerance, and `is_na_real` from `r0_wasm::value` (already imported at the top of the file).
- `approx(...)` is assumed to return `R0Val::Dbl`, consistent with the printed output. If it returns another variant, the test fails on the variant match, not the value. Treat that as a STOP and report, not a silent change to the match.
- Helpers `eval`, `eval_err`, `assert_val` stay as they are. New helpers are local to the `pedon_` section.
- Risk: the raw-string script must be copied exactly. Any drift from `src/main.rs` changes the outputs, so re-run `cargo run --release` after copying if a value is off.

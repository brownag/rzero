## Notes
- Value asserts migrated: 26.
  - `is.finite` group: 7 (`c(1.0, 0.0, -0.0, Inf, -Inf, NaN, NA_real_)`, `c(1L, 0L, -1L, NA_integer_)`, `c(TRUE, FALSE, NA)`, `c("a", "b", NA)`, `1:3`, `c()`, `numeric(0)`).
  - `is.infinite` group: 7 (same argument set as `is.finite`).
  - `anyNA` group: 12 (`c(1.0, 2.0)`, `c(1.0, NA_real_)`, `c(1.0, NaN)`, `c(1L, 2L)`, `c(1L, NA_integer_)`, `c(TRUE, FALSE)`, `c(TRUE, NA)`, `c("a", "b")`, `c("a", NA)`, `1:10`, `logical(0)`, `c()`).
- Error asserts kept in Rust: 12 (`eval_err(...).contains` / `.starts_with`: 4 per function. `list(a = 1)` and `data.frame(a = 1)` give `Unsupported type`; the no-argument call gives `missing argument 1`; `(1, 2)` gives `TooManyArguments:`).
- Exclusions applied: none. No H4 known divergence touches these three functions.
- Risks:
  - `NaN` and `NA_real_` in the `c(...)` vectors: the harness must canonicalize `is.finite`/`is.infinite` logical results the same as GNU R. Both sides give plain logical vectors, so this should match.
  - `is.finite(c())`, `is.infinite(c())`, `is.finite(numeric(0))`, `is.infinite(numeric(0))`, `anyNA(logical(0))`, `anyNA(c())` must give empty or FALSE results on both sides. GNU R gives `logical(0)` for the `is.*` calls and `FALSE` for `anyNA` on empty input. Same `c()` pattern as 8.1.3, 8.1.4 and 8.1.6.
  - `anyNA(c(1.0, NaN))` must be TRUE on both sides (GNU R counts NaN as NA for `anyNA`).
  - `is.finite(c("a", "b", NA))` and `is.infinite(c("a", "b", NA))` return all FALSE on both sides. No warnings expected.

## Notes
- Value asserts migrated: 20 expressions.
  - `trunc` values: 6 (`c(1.2, ...)` mixed signs and signed zero, `c(Inf, -Inf)`, `1:3`, `c(1L, -2L)`, NA/NaN mix, `numeric(0)`).
  - `round` values: 14 (ties-to-even at digits 0, positive and negative digits, named and scalar digits forms, NA/NaN and integer NA, Inf, `numeric(0)`). The two `match eval(...)` blocks count as one expression each.
- Error asserts kept in Rust: 10.
  - `trunc`: 3 (`trunc("abc")` TypeError, `trunc()` missing argument, `trunc(1, 2)` TooManyArguments).
  - `round`: 7 (`digits` NA / NA_integer_ / NA_real_ / NaN / `1:2`, all `contains "round:"`; `digits = "2"` TypeError; `round()` missing argument).
- Exclusions applied (bare `c()` as a math-function argument, H4-style, per the task brief):
  - `trunc(c())`: GNU R errors on NULL ("non-numeric argument to mathematical function"). Excluded from the corpus and reported. It stays in Rust as an `assert_val`.
  - `round(c())`: same divergence. Excluded from the corpus and reported. It stays in Rust as an `assert_val`.
  - Net: 22 Rust value asserts in the function, 20 migrated, 2 kept in Rust only.
- Kept: `numeric(0)` empty inputs for `trunc` and `round` (valid in both).
- Risks:
  - Signed zero: `trunc(-0.0)` and `round(c(-0.5, ...))` yield `-0`. The Rust asserts use `f64 ==`, which ignores the sign. If the canonical form prints `-0` and `0` differently, these can mismatch.
  - Integer input type: `trunc(c(1L, -2L))` and `round(c(1L, NA_integer_))` are asserted as `Dbl` in Rust. If GNU R returns integer for `round` on integer input, the canonical type may differ.
  - Rounding edge: `round(c(1.2345, 1.2355), 3)` depends on R 4.x round-to-nearest on the stored double. Rust expects `1.236`. Not verified here (no Rscript run in this phase).
  - NA vs NaN: `round(c(1.5, NA_real_, NaN))` and `trunc(c(1.5, NA_real_, NaN, NA))` need the list canonicalization to keep NA and NaN distinct.

# 12.4.1 -- Closure scoping rule (G28)

## Goal
Top-level functions resolve free variables live in the global env at call time; functions created inside a call keep the creation-time snapshot of the enclosing frame.

## Notes
- `captured_env` set/read: `src/vm.rs` L17 (field), L158 (named def), L418 (anon `FnDef`), L507 (`call_user` clone); `src/value.rs` L338 (a unit test constructs `UserFn` literally).
- Top-level env is NOT stored in `self.globals` during a run: `eval_script` clones `globals` into a local `env`, evals, writes back at the end. So `call_user` cannot see the live global env today; step 6 handles it.
- Named definitions always go to `self.functions` (even inside a function body); with step 4 a named def at depth > 0 snapshots, at depth 0 is live.
- Calls resolve `env` Fn value first, then `self.functions`; both go through `call_user`.
- Search by keyword and by eye found no conformance test explicitly about snapshot/closure; the exact list of tests that change can only be determined by running step 7. Existing closure tests near conformance.rs L2442-2462 (`mk`, `make(2)(3)`) are nested cases and expected to keep passing. Candidates are none known; will report "none" if none fail.

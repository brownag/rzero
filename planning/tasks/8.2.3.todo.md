## Notes
- Value asserts migrated: 21 expressions.
  - Values at 0/1: 6 (`sin(0)`, `cos(0)`, `tan(0)`, `asin(0)`, `acos(1)`, `atan(0)`).
  - Non-zero vectors: 3 (`sin(c(0.0, 1.5707963267948966))`, `cos(c(0.0, 3.141592653589793))`, `atan(c(0.0, 1.0))`). The Rust asserts use a 1e-12 tolerance, the corpus compares exact values (see Questions).
  - Domain NaN: 2 (`asin(c(2.0, -2.0))`, `acos(c(2.0, -2.0))`), both asserting NaN and not NA.
  - Int/Range promotion: 2 (`cos(0L)`, `sin(0L:0L)`).
  - NA/NaN preservation: 6 (the `for f in [...]` loop expanded to one element per function, `c(0.0, NA_real_, NaN)`).
  - Empty input: 2 (`sin(c())`, `cos(numeric(0))`).
- Error asserts kept in Rust: 5 (`eval_err(...)`):
  - `sin("a")` TypeError, `cos(TRUE)` TypeError, `tan(list(a = 1))` TypeError (all `starts_with`).
  - `sin()` missing argument (`contains "sin: missing argument 1"`).
  - `sin(1, 2)` TooManyArguments (`starts_with`).
- Exclusions applied: none. No H4 or D-8.x entry names this function.
- Risks:
  - NaN vs NA: `asin`/`acos` results and the NA/NaN loop need GNU R's NaN and NA to stay distinct through list canonicalization. The Rust asserts check this explicitly with `is_na_real`.
  - Floating-point last-bit differences from GNU R libm on `sin`/`cos`/`atan` for the non-zero inputs. The inputs are exact-at-zero or give exact results (`sin(pi/2)`=1, `cos(pi)`=-1, `atan(1)`=pi/4), so no mismatch is expected.
  - The NA/NaN loop has six near-identical elements. Each must be written out explicitly, since R0 has no loop form in the corpus.

## Notes

Analysis facts (from `tests/conformance.rs`):
- `PEDON_SCRIPT` is a raw string at lines 212-238. It is indented by 8 spaces and begins with a newline; the R0 tests use it as-is.
- The only R0-only constructs in the script are the signature `hz: df, z_min: dbl = 0, z_max: dbl = 100` and the `-> dbl` return annotation on the header line. Those are the only changes the spec requires.
- `|>` IS present, at two places: `valid_thick |> sum(na.rm = TRUE)` (line 219) and `pedon |> depth_weighted_mean(0, 100)` (line 230). Both are valid in GNU R 4.1+, so they stay.
- Other constructs used: `pmax`, `pmin`, `is.na`, `which`, `approx`, `data.frame`, `NA_real_`, `return(...)`, `if`, `list(...)`, `1L`/`5L`/`99L` integer literals. All are base R.
- Rust anchors that the GNU R output must agree with: `pedon_depth_weighted_clay_0_100` expects `wt_clay_0_100cm` = 25.666 (tol 1e-3); `pedon_approx_25_50_85` expects `interp_25_50_85$y` = [21.7381, 29.0526, 28.7059]; `pedon_remaining_oob` expects `remaining_oob` = [14.5, NA, NA]; `pedon_result_is_list` expects a list result.
- `tests/gnu_r.rs` `r0_corpus_matches_gnu_r` reads every `.R0` file in `tests/r0/`, compares R0 vs GNU R canonical output, and fails on mismatch unless the stem is in `allowlist.txt`. A new file needs no registration.
- Repo constraints honored: no edits to `tests/conformance.rs`, `src/`, `allowlist.txt`, or `planning/STATE_9.md`.
- Style reference: `tests/r0/g8_extensions.R0` is a single `list(...)` expression with named fields and no function definitions. The new file is a multi-statement script whose last expression is the `list(...)`, which the harness takes as the result.

Risks:
- The harness runs GNU R via `Rscript`. If `Rscript` is not on PATH, `make test-gnu-r` fails before comparison (Makefile guard). Verify with `command -v Rscript` before step 7.
- `approx()` output shape (`list(x, y)`) and float canonicalization must match between R0 and GNU R. The Rust test uses a 1e-3 tolerance; the harness canonical form may be stricter. A mismatch would be a harness or R0 divergence, which is out of scope to fix here.
- R0's `return()` inside `if` and the `pedon |> f(0, 100)` pipe call must be accepted by the R0 parser. Covered by the conformance tests already, but this is the first corpus file to combine them.

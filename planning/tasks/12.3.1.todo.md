# 12.3.1 -- `Expr::Call` takes a callee expression (G27, part 1)

## Goal
Change `Expr::Call.func` from `String` to `Box<Expr>` and parse calls as a postfix operator on any expression, with the VM still dispatching only `Ident` callees (identical behaviour for existing scripts).

## TODO items
- [ ] 1. `src/ast.rs`: change `Call { func: String, .. }` to `func: Box<Expr>`.
- [ ] 2. `src/parser.rs`: extract the argument-list loop (currently inline in the `Tok::Ident` arm, ~lines 290-312) into `fn parse_call_args(&mut self) -> Result<Vec<(Option<String>, Expr)>, String>` (consumes through `)`, assumes `(` already consumed). Logic copied verbatim.
- [ ] 3. `src/parser.rs`: add `Tok::LParen => Some(21)` to `postfix_bp`, and a `Tok::LParen` arm in the postfix `match` in `parse_expr` (~line 75-118): `lhs = Expr::Call { func: Box::new(lhs), args: self.parse_call_args()? }`.
- [ ] 4. `src/parser.rs`: collapse the `Tok::Ident(name)` prefix arm to `Tok::Ident(name) => Ok(Expr::Ident(name))` (call now comes from the postfix loop).
- [ ] 5. `src/parser.rs`: `%in%` desugar (~line 141) -> `func: Box::new(Expr::Ident("%in%".into()))`. `desugar_pipe` needs no change (moves `func` through, now a Box).

## Notes
- Only 3 files reference `Call` in `src/`: `ast.rs:69`, `parser.rs` (lines 141, 312, 348-359, tests 413/421/437), `vm.rs:383`. `tests/` has no match. `src/transpile.rs` has NO `Expr::Call` use (it operates on tokens, `Tok::Fn`), so no risk there; nothing to edit.
- `Expr` derives `Clone, Debug` only (no PartialEq), so `Box<Expr>` is fine; `desugar_pipe` uses `lhs.clone()` on Expr, unaffected. Parser tests compare Debug strings, hence step 6.
- Postfix site: `parse_expr` loop with `postfix_bp` (binding power 21, same as `[`, `[[`, `$`), so `l$f(1)` becomes `Call{Field}` (errors "callee not supported yet" until 12.3.2) -- previously this was a parse error, so no regression for working scripts.
- Newlines: lexer emits terminator tokens for `\n`/`;` outside parens, so `x\n(y)` does not become a call. `if (c) (x)`, `fn(x) (x)` parse the body via a fresh `parse_expr`, unaffected. Inside parens newlines are suppressed (`(a\n(b))` would now be a call; previously a parse error).
- `Placeholder` args and pipe: `x |> f(_)` still yields `Call` from `parse_expr(12)`; `desugar_pipe` unchanged.
- Risk: `Ident`-named intrinsic-like keywords handled in `parse_prefix` (if/while/for/function) are separate tokens, unaffected.

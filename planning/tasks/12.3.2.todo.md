# 12.3.2 -- Calls through function values (G27, part 2)

## Goal
Calls evaluate any callee expression to an `R0Val::Fn` and invoke it via `call_user`, and a bare identifier naming a stored function evaluates to `R0Val::Fn`.

## Notes
- `Expr::Call.func` is `Box<Expr>`; Ident arm currently does `self.functions.get` then `call_intrinsic`; others error.
- `call_user(func: &str, &UserFn, args)` binds via `bind_args`, evaluates defaults in a clone of `captured_env`; the `&str` is only for error messages.
- Eval returns `Result<ControlFlow, String>`; args use `ControlFlow::Val(v)` else `return Ok(other)`.
- `$` -> `self.field` clones `cols[i]`, `[[` -> `subset2`; an `R0Val::Fn` stored in a list is returned as-is, so `l$f` yields Fn. Parser already makes `l$f(1)` a `Call` on a `Field` callee (12.3.1). Assumes `subset2` on a list elem returns the element unchanged (to verify by test).
- Assignment `v <- (fn..)` stores in `self.functions` (parens not kept), hence the Ident fallback; this also makes `v` a Fn value when passed as arg.
- Risk: a param named `h` holding a Fn must win over a same-named global function, so env is checked before `self.functions` for Ident callees. This only changes behaviour where a Fn value sits in env, which could not be called before.
- Risk: an arg whose value is a Fn inserted into `local_env` is fine (`R0Val` already has `Fn`).
- Ident fallback inside `Assign` targets is untouched (those use their own paths).

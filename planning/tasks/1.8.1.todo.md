## Notes
- Spec anchors: INITIAL_SPEC.md §5 EBNF (`Term` at line 247, `PipeExpr` at line 275) and §4 precedence table (`|>` at level 8, `/` tighter than `|>`).
- Lexer (`src/lexer.rs`): `Tok::Pipe`, `Tok::Plus`, `Tok::Star`, `Tok::Slash` and the other operators suppress newlines via `suppresses_newline()`. Newlines are emitted as `Term` otherwise, so `1\n2` gives two statements.
- Parser (`src/parser.rs` ~line 1509-1525): `x |> f(a)` becomes `f(x, a)`. `_` placeholder replaces the argument. A non-call RHS yields exactly `Right-hand side of '|>' pipe must be a function call`.
- `approx` (`src/vm.rs` ~line 730, 862) takes named args `x, y, xout`. The existing unit test `approx_and_named_args` already runs `xout = _` through the VM, so `pipe_placeholder_substitution` is supported by 1.5.3.
- `TRUE`/`NA` lex as `LglLit` (`src/lexer.rs` 231-233). `na.rm` is still handled in `eval_call`, per D15.
- Test form: `R0Vm::new(fuel)` and `eval_script`, as in `src/vm.rs` tests (`run`/`same`). Test names carry the `newline_` or `pipe_` prefix so the filters work.
- Constraints honored: only `tests/conformance.rs` is created. No `src/` edits. No pushes or remote operations. Planning artifacts are committed separately with `docs(planning):`.
- Risks: the exact `Dbl` vs `Int` result from `sum` on Dbl input is not verified from code yet; the test expectation uses what the evaluator returns, and a mismatch would be a `src/` question (STOP and report), not a test edit.

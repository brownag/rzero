## Notes
- Repo state: `master`, clean tree. `src/value.rs` is `//! Runtime value representation.` only. `src/lib.rs` declares `pub mod value;`. No other module references `value::` items, so the new public API breaks nothing.
- Spec vs prototype differences:
  - Spec §2.1 lists six tags (Dbl, Int, Lgl, Chr, Range, Df). Neither the spec nor the prototype gives `List` or `Null` a tag. D12 adds `List`. Its tag value is in Questions 2.
  - Spec §2.1 `Range` payload is `start:i32, end:i32`. The prototype variant also carries `step`. The R0Vec layout is not used for `Range` in this task, so this does not affect the port.
  - Prototype `Display` for `Df` prints `<R0 df: ...>`, but the prototype has no `List` arm. This task adds one (E10, D12).
  - Prototype `is_na_real` is `is_nan()`, not a payload check. The constraint keeps it. It is noted here, not changed.
  - Prototype `Range::len` uses `((end - start) / step).abs() + 1`. For a negative step with `end < start`, it returns a count that disagrees with `materialize_int`. See Questions 5.
- Constraints honored: only `src/value.rs` is edited. No lexer, parser, vm, or isa changes. No constructors on `R0Vec`. No allocation code. No HashMap import.
- Risks:
  - `cargo clippy --all-targets -- -D warnings` may flag the prototype `len()`. The `is_empty` item covers that.
  - If `vm.rs` or `isa.rs` already fail clippy, the gate fails for reasons outside this task. Step 9 STOPs in that case.

## Questions
1. `R0Vec::tag(&self)` return type. The spec names `TypeTag` but defines no Rust type. Default: return `u32`, masked to bits 0..3 (`tag_flags & TAG_MASK`). Add a `TypeTag` enum instead?
2. Tag value for `List`. The spec's bit 0..3 tag space is 4 bits and lists six tags. Default: `TAG_LIST = 6`, next free value. `Null` gets no tag.
3. `na_of_type_like` for variants with no NA form (`Range`, `Df`, `List`, `Null`). Default: `Range` gives an `Int` vector of NAs (D3 integer-type rule), and `Df`, `List`, and `Null` return `R0Val::Null`. Confirm?
4. Add `is_empty()` even though the prototype has none? It is needed to pass the clippy gate. Default: yes, one line.
5. Prototype `Range::len` disagrees with `materialize_int` for a negative step where `end < start` (e.g. `start=5, end=1, step=-1`). Default: port unchanged, since this task ports the prototype, and log the defect under `## Discovered`. Fix it here, or defer to the vm task?

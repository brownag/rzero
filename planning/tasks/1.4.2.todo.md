## Notes
- Analysis, opcode count (INITIAL_SPEC.md lines 561-621, named opcodes only, wildcards expanded per the task spec):
  - 0x00-0x0F: LOAD_CONST, MOVE_COW, FREE_DEAD, MAKE_RANGE = 4
  - 0x10-0x1F: S_ADD_F64, S_SUB_F64, S_MUL_F64, S_DIV_F64, S_CMP_LT_F64, FOR_RANGE_STEP = 6
  - 0x20-0x3F: FUSE_TILE_BEGIN, FUSE_TILE_END = 2; arithmetic TILE_{ADD,SUB,MUL,DIV,PMIN,PMAX,POW} x {VV,VS,SV} = 21; TILE_{EXP,LOG,SQRT,ABS,ROUND} = 5; TILE_{CMP_EQ,CMP_LT,CMP_LE,AND_LGL,OR_LGL,NOT_LGL,IS_NA} = 7; TILE_IFELSE = 1. Subtotal 36.
  - 0x40-0x4F: REDUCE_SUM_F64, REDUCE_MEAN_F64, REDUCE_MIN_F64, REDUCE_MAX_F64, REDUCE_ANY_LGL, REDUCE_ALL_LGL, CUMSUM_F64, DIFF_F64 = 8
  - 0x50-0x5F: SUBSET_MASK, SUBSET_IDX, SUBSET_SCALAR, ASSIGN_SUBSET, WHICH_LGL, MATCH_VEC, APPROX_LINEAR, FIND_INTERVAL = 8
  - **Total named opcodes: 62** (spec header says "~64"). Recorded as the expected count.
  - **Overflow:** the 0x20-0x3F family has 32 slots but 36 names. Family ranges cannot all hold.
- TileKernel: 20 names, matching the task spec list exactly.
- E3 applied: the bit-field table in `docs/ARCHITECTURE.md` (line ~170) matches the task spec (opcode[31:24], A[23:16], B[15:8], C[7:0]).
- Constraints honored: layout and encoding only, no codegen, no execution (D5). No `unsafe`. No dependencies added. Only `src/isa.rs` in scope.
- Lazy choices: no serde, no `From<Opcode> for u8` beyond `as u8`, no name lookup table, no Display impl.
- Risks:
  - 0x20 overflow (see Q1) changes every discriminant after it.
  - `TILE_IFELSE` takes four operands (A, B, cond, yes, no) but `Instr` has three byte fields.
  - `FOR_RANGE_STEP` takes two registers plus a 16-bit offset. Fits A, B, and Bx only if the register operands are A and B, and the offset is not in C.
  - Clippy `-D warnings` may flag unused `TileKernel` variants if the enum is private. Keep it `pub`, same as `BinOp` in 1.3.2.

## Questions
1. The 0x20-0x3F block has 36 named opcodes but only 32 discriminant slots. Options: (a) extend the block into 0x40+ and renumber, (b) move the 4 overflow names (e.g. the TILE_ARITH variants of POW) to a new range, (c) amend the spec. Default if no answer: (a), sequential assignment with the 0x20 family base kept and later families shifted.
2. `TILE_IFELSE` has four operands. `Instr` has A, B, C only. Default: encode A, B, C in the word and document that the fourth operand (no_tile) goes in the following word. No codegen uses it yet.
3. `FOR_RANGE_STEP r_iter, r_limit, offset16`. Default: r_iter = A, r_limit = B, offset16 = Bx (B and C combined), so r_limit must fit in the 8-bit field. Confirm, or specify another split.
4. `TILE_SUM_ACCUM` appears in the spec's §2 "Fused Reductions" text but not in the §4 opcode list (lines 561-621). Default: exclude it, count stays 62. Include it or not?
5. The spec gives family ranges but no per-opcode discriminants. Default: sequential numbering in the listed order from each family base, with `_VV`, `_VS`, `_SV` in that order. Acceptable?

## Discovered
- **E13 ISA opcode block overflow** (INITIAL_SPEC.md §4, 0x20-0x3F): the block has 32 slots but 36 named TILE opcodes, plus TILE_SUM_ACCUM (named in §3.3) makes 37. Repair (approved): TILE block 0x20-0x44, REDUCE/CUMULATIVE 0x45-0x4C, SUBSET 0x50-0x57. 0x00-0x0F and 0x10-0x1F unchanged. Total 63 named opcodes.
- **Open, not implemented:** `FOR_RANGE_STEP` is approved as A=r_iter, B=r_limit (8-bit), Bx=offset16. Bx is B and C combined, so it overlaps B. The approved layout cannot hold both r_limit and a 16-bit offset in one word. No code encodes this opcode yet, so `src/isa.rs` is unaffected. Needs a decision before codegen (task 1.5.x).

# 10.1.2 -- G3: lexer validates matching open and close delimiters

## Goal
The lexer rejects a closer that does not match the innermost open delimiter, a stray closer, and an opener left open at end of input, each with a `ParseError:` message.

## Notes
- Tracing `x[[a[1]]]`: the inner `]]` sees `[` on top, so it falls to single `]` (pops `[`), then the last `]]` closes `[[`. Valid, so the strict rule holds.
- `x[[1]` is currently accepted (a single `]` pops `[[`). It becomes an error, which is the intended G3 behaviour.
- Newline suppression (`tokenize` ~137) reads `stack`; it is unchanged for valid programs.
- Scope: `src/lexer.rs` only. No parser change, no token change.

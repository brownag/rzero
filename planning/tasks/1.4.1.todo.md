## Notes
- Repo state: `master`, clean. `src/parser.rs` is `//! Parser producing the AST from tokens.` only. `src/lib.rs` already has `pub mod parser;`, so no `lib.rs` change.
- Public API used: `lexer::{Tok, tokenize}` (`tokenize(&str) -> Result<Vec<Tok>, String>`; `Tok` derives `Clone, Debug, PartialEq`). `ast::{Expr, BinOp, UnaryOp}`. `Expr` variants per `ast.rs`: `Call { func: String, args: Vec<(Option<String>, Expr)> }`, `Binary(BinOp, Box, Box)`, `Unary(UnaryOp, Box)`, `Placeholder`, `Ident`, `Block(Vec<Expr>)`, etc. `ast.rs` has `Expr` with `Clone, Debug` only, so tests use Debug strings.
- Lexer emits `Tok::Placeholder` for `_` and `Tok::InOp` for `%in%`. Lexer also emits `Tok::Arrow` (`->`); the parser has no infix arm for it, so it errors as "Unexpected token". Spec §5 grammar only uses `->` for fn return-type annotations, which the port handles in `Tok::Fn`. Matches grammar, no change.
- Binding power check against spec §4 (tightest first: postfix, `^` R, unary, `:`, `%%`/`%/%`/`%in%`, `* /`, `+ -`, `|>`, comparisons, `!`, `& &&`, `| ||`, `<- =` R):
  - Match: postfix 21; `^` (20,19) right; `:` (19,20); `%%`/`%/%`/`%in%` (17,18); `* /` (15,16); `+ -` (13,14); `|>` (11,12); comparisons (9,10); `&`/`&&` (5,6) above `|`/`||` (3,4); `<-`/`=` (2,1) right. `!` operand 7 gives comparisons and `|>` tighter, `&` looser, which matches spec.
  - **Deviation:** unary `-`/`+` operand bp 17 lets `:` (19) and `%op` (17) bind inside the operand. Spec ranks unary above both. Effect in prototype: `-1:3` = `-(1:3)`, `-5 %% 3` = `-(5 %% 3)` = -2. Spec gives `(-1):3` and `(-5) %% 3` = 1. Fix planned: operand bp 20. `-2^2` still gives `-(2^2)`.
  - Spec table header says "highest (1) to lowest (11)" but the table has 13 rows. I used row order.
- Desugar notes: the prototype replaces every `_` and clones the LHS. Spec says "replace it". See Question 2.
- Risks: `Parser::next` does not advance past the end; the `LBrace` arm relies on `pos -= 1`, which is safe because `{` is never last. `unreachable!()` in the binary arm must stay unreachable after the `InOp` branch is added. Clippy may flag `_ => unreachable!()` shapes; keep as is unless clippy complains.
- Constraints: no lexer or AST edits. Parse errors stay plain `String`. No files outside `src/parser.rs`.

# 1.8.5 -- conformance C5: fuel

## Goal
Add three `fuel_` tests to `tests/conformance.rs` that drive `r0_wasm::vm::R0Vm` directly and assert that an infinite loop and a small-budget vector op both halt with `ErrFuelExhausted:`, and that a finite loop completes with `i == 5`, with no `src/` changes.

## Notes
- Only file in scope: `tests/conformance.rs`. No `src/` edits. A failure caused by a `src/` bug: STOP and report. A second identical failure on the same test: STOP.
- Analysis of `src/vm.rs` (read, not yet run):
  - `consume_fuel(units)` subtracts `max(1, units)` and returns `Err("ErrFuelExhausted: ...")` when fuel <= 0. Errors propagate through `eval_script` via `?`.
  - `eval()` calls `consume_fuel(1)` on every expression node. `Expr::While` re-evaluates `body` each iteration, so `while (TRUE) { x <- 1 }` burns fuel every pass and halts on 10_000.
  - Finite loop: 5 iterations, a few dozen node evals each, far under 10_000. `i` stays `Dbl` (`0` and `1` are double literals), so the result is `R0Val::Dbl(vec![5.0])`.
  - Vector op: `1:10000` is handled in `eval_binary` (`BinOp::Colon`) and returns `R0Val::Range` with no fuel charge. `x + 1` reaches `broadcast_len(10000, 1) = 10000`, then `consume_fuel(10000)` at `vm.rs` (~line 311) with fuel 100 -> error. Expression errors as planned.
- Constraints honored: `R0Val` has no `PartialEq`, so comparisons use `Debug` strings or `match`. `eval`/`eval_err`/`assert_val` helpers hard-code a 100_000 budget, so the fuel tests build their own `R0Vm::new(...)` calls with the budget the task specifies.
- Name check: the `fuel_` prefix in `tests/conformance.rs` does not collide with `fuel_exhausts_on_infinite_loop` in `src/vm.rs` unit tests (separate test target).
- Risks: `R0Vm::new(100)` must not be exhausted before the broadcast by the earlier nodes (assignment, colon, binary, idents). Node count is far under 100, but this is confirmed only when the test runs. If it does not hold, STOP and report.
- Not a test-only concern: `1:10000` is lazy, so the vector op only charges fuel at the broadcast. That matches the spec's "consumes fuel per element" intent.

## Notes
- Value asserts migrated: 11 expressions (of 12 value expressions in the Rust function).
  - Quadrants: 1 expression (6 elements).
  - Named arguments: 2.
  - Recycling: 2. The Rust check for `atan2(c(0, 1, 0, -1), 1)` is length-only; the corpus carries the full value (`0, pi/4, 0, -pi/4`), which `Rscript` confirmed.
  - Empty: 1 (`numeric(0)`, matches GNU R `numeric(0)`).
  - NA/NaN: 5 of 6 (see exclusion below).
- Error asserts kept in Rust: 6 (eval_err `starts_with`/`contains`).
  - `ErrDimensionMismatch`: 2 (`atan2(c(1, 2), c(1, 2, 3))`, `atan2(1:3, 1:2)`).
  - `TypeError`: 3 (`atan2(c(), 1)`, `atan2(1, c())`, `atan2(c(), c())`). Bare `c()` args to `atan2`: GNU R errors "non-numeric argument to mathematical function" (verified by Rscript). R0 also errors, so no H4 value case arises here.
  - Missing argument: 1 (`atan2(1)`).
- Exclusions applied:
  - `atan2(NaN, NA_real_)`: NEW divergence, found by `Rscript` check. GNU R returns `NA` (R's math2 gives NA when either operand is NA). The Rust assert expects `NaN` (first-operand-wins, B8). Excluded from the corpus per H4, kept as-is in Rust. Not adapted.
- Verified with Rscript 4.6.2 (read-only, no harness run): `atan2(NaN, NA_real_)` = NA, `atan2(NA_real_, NaN)` = NA, `atan2(NaN, 1)` = NaN, `atan2(1, NaN)` = NaN, `atan2(numeric(0), numeric(0))` = numeric(0), `atan2(y = 1, x = 0)` = pi/2.
- Risks:
  - The `atan2(NA_real_, NaN)` corpus element depends on the canonical form separating NA from NaN. Rscript gives NA for it, which matches the Rust assert. Confirm in the harness.
  - Quadrant values `pi`, `3pi/4` depend on canonical float precision. Same risk as 8.2.3.

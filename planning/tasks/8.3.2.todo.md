H4 check: the three bare `c()` value asserts (`match(c(), c(1, 2))`, `match(c(1, 2), c())`, `match(c("a"), c())`) are not errors in GNU R, since `match` accepts NULL and returns `integer(0)` or all-NA. Expected to stay in the corpus. Not verified by running Rscript (out of scope for this phase).
- D-8.4 check: no `var`/`sd` NaN here. The NaN elements are `match` table and x inputs (`c(NA, NaN)`). Per the rule, a NaN element that mismatches GNU R is excluded and reported. Expected to match GNU R (NA does not match NaN, NaN matches NaN).
- Risks: (1) `match(c(1, 2, 3), c(2, 3, 4), 99L)` uses positional `nomatch`. If R0 rejects positional, that element is the first suspect. (2) `nomatch = 0` (double) returns Int in R0; GNU R returns integer. Canonical comparison should match, as for earlier tasks. (3) `match(numeric(0), ...)` and `match(c(), ...)` return integer(0); canonicalized as in 8.2.x empty cases.

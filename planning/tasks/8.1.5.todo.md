## Notes
- Value asserts migrated: 11
  - `rep(1:3, times = 2)` (Int, prefix `times_*`)
  - `rep(1:3, 2)` (Int, positional `times`, `times_*`)
  - `rep(1:3, 0)` (empty Int, `times_*`)
  - `rep(1:3, each = 2)` (Int, `each_*`)
  - `rep(1:2, times = 2, each = 2)` (Int, `both_*`)
  - `rep(1:3, length.out = 5)` (Int, `length_out_*`)
  - `rep(1:3, times = 10, length.out = 4)` (Int, `length_out_*`)
  - `rep(1:2, each = 3, length.out = 4)` (Int, `length_out_*`)
  - `rep(c(), times = 3)` (Null, `empty_*`)
  - `rep(c(), each = 3)` (Null, `empty_*`)
  - `rep(c(NA_character_, "x"), each = 2)` (Chr with NA, `na_*`)
- Error asserts kept in Rust: 6 (`eval_err` with `contains`): empty vector with `length.out`, negative `times`, negative `each`, negative `length.out`, `times = NA_integer_`, missing argument 1.
- Exclusions applied: all `eval_err` asserts stay in `conformance_g6_rep`; none copied to the corpus.
- Risks: the `c()` Null elements follow the 8.1.3 and 8.1.4 gotcha (match GNU R). Named `times =`/`each =`/`length.out =` args follow the 8.1.1 `numeric(length = 2)` gotcha. The `NA_character_` element is a Chr NA shape; 8.1.1 showed empty-string canonicalization matches, but an NA string is new to the group, so it is the most likely harness mismatch point.
- Source lines read: `tests/conformance.rs` L640 to L668 (function body only).

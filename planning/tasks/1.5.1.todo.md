## Notes
- **Analysis facts.**
  - Reference lines 1529-1886 are about 358 lines. The port is roughly 300-350 lines of Rust, so it fits in 12 steps.
  - `BinOp` already derives `Copy` (ast.rs:8). E7 is already satisfied, so no change is needed in ast.rs.
  - `parser.rs:106` rewrites `Tok::InOp` into `Expr::Call`. `BinOp::InOp` is never produced, so keeping it out of dispatch is safe.
  - `lexer.rs:231-234` lexes `TRUE`, `NA`, `NA_real_`, and `NaN`. The `&` and `FALSE` literal tests need no vector constructors.
  - `value.rs` exports `KLEENE_AND_LUT`, `KLEENE_OR_LUT`, `KLEENE_NOT_LUT`, `LGL_*`, `NA_INT`, `na_real`, `is_na_real`, `R0Val` with `len`, `materialize_int`, `promote_dbl`. `R0Val` is `Clone`. `Expr` and `UserFn` clone cleanly.
  - `Expr::Index1` assign, `Index1` read, and `IndexScalar` / `Field` arms are inline in the reference. The spec requires them to delegate to stubs, so each arm calls a stub and returns its `Err`.
  - The reference `eval_call` (INITIAL_SPEC.md:1978) is outside the 1529-1886 range. Call dispatch is stubbed here (see Question 2).
- **Constraints honored.** Only `src/vm.rs` is edited. `parser.rs`, `lexer.rs`, `value.rs`, `ast.rs` are untouched. No `%in%` logic (D17). No subsetting or intrinsics (1.5.2 and 1.5.3). Error prefixes (`ErrFuelExhausted:`, `ErrDimensionMismatch:`, `ErrInvalidCondition:`, `ErrNotImplemented:`) are kept verbatim.
- **Risks.**
  - The acceptance examples `1 + c(10, 20)` and `c(1,2,3,4) + c(10,20)` need `c()`, which is 1.5.3. They cannot pass in 1.5.1 as written. See Question 3.
  - `for` loops need element extraction. The reference uses `eval_subset`, which is stubbed here. See Question 1.
  - `consume_fuel` is called per node. Fuel tests use a small budget so they stay fast.
  - Clippy `-D warnings` may flag unused stub parameters. Use `_` prefixes if needed, not `#[allow]`.

## Questions
1. **For-loop element access.** The reference `For` arm calls `eval_subset(&seq, idx)`, which is stubbed in this task, yet the spec puts `for` in 1.5.1. Proposed fix: add a private `fn elem_at(seq: &R0Val, k: usize) -> Result<R0Val, String>` in the `For` arm only, handling Dbl/Int/Lgl/Chr/Range with a 1-based index. It is not a subset operation, and it is replaced by the 1.5.2 code path. Approve, or say to stub `for` instead?
2. **User-defined function calls.** The reference `eval_call` checks `self.functions` before intrinsics. The spec stubs only `call_intrinsic`. Proposed fix: the `Expr::Call` arm calls `call_intrinsic` only, so user functions are not callable until a later task. Alternative: the arm checks `self.functions` first and invokes the body with the reference's binding logic. That adds about 40 lines and is not in the stub list. Which one?
3. **Vector-dependent acceptance tests.** The 1.5.1 acceptance tests `1 + c(10, 20)` and `c(1,2,3,4) + c(10,20)` need `c()`, which is not implemented until 1.5.3. Proposed fix: the tests seed `vm.globals` with `R0Val::Dbl` values directly (`globals` is `pub`), and the `c()` form moves to 1.5.3's test list. Approve?
4. **`BinOp::InOp` arm.** The reference `eval_binary` has an `InOp` block and `_ => unreachable!()`. Proposed fix: drop the `InOp` block and add an `InOp` arm that returns `Err("ErrNotImplemented: BinOp::InOp")`. The parser never emits it, so the arm is unreachable in practice, and `unreachable!()` is avoided. Approve?
5. **Stub signatures.** The reference call sites are `self.subset(&base, &sub)`, `self.subset_assign(current, &idx, &val)`, and `self.call_intrinsic(func, args)`. `index_scalar` and `field` take the target and index value as in the reference `IndexScalar` / `Field` arms. Proposed fix: keep those shapes, with `Result<R0Val, String>` returns, and make the stubs `fn` methods on `R0Vm`. OK?

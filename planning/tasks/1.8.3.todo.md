## Notes
- Only file in scope: `tests/conformance.rs`. No `src/` edits. If a test fails because of a `src/` bug, STOP and report (do not fix). A second identical failure on the same test = STOP.
- Spec §3.4 (INITIAL_SPEC.md:194): positive indexing returns length(i), OOB/NA yields NA of typeof(x); logical mask requires length N or 1, NA mask yields NA; negative drop mixing with positive or NA traps `ErrMixedSubscript`. D3: OOB NA is `NA of typeof(x)`.
- Evaluator facts (`src/vm.rs`, verified by reading):
  - `subset` (vm.rs:393): Range base materializes to Int; positive OOB/NA -> None -> NA of base type via `gather`; negative drop path; mixed-sign or NA with negative -> `ErrMixedSubscript:`.
  - `index_scalar` (vm.rs:457): OOB or NA index -> `ErrBoundsTrap:`; scalar element via `elem_at`.
  - `subset_assign` (vm.rs:481): D3 keeps target type, only Int->Dbl promotion; mask positions with TRUE are assigned.
  - Unit tests in `src/vm.rs` (`oob_and_range_subsetting_preserve_type`, `mixed_and_bounds_traps`, `logical_mask_length_and_na`, `subset_assign_mask_and_index`) already pin the same values, so the expected values are confirmed against current behavior.
- Helpers: `is_na_real` is `pub` in `r0_wasm::value` (value.rs:16) and `NA_INT` is `pub const` (value.rs:10). Import them only if used.
- Comparison: `R0Val` has no PartialEq. Use the existing `assert_val` (Debug) for exact values. For Dbl NA, do NOT rely on Debug output of the NaN payload; use `match` on `R0Val::Dbl(v)` with `v.len() == 1 && is_na_real(v[0])`, as the unit test `assert_na_dbl` does.
- Discovered-item exclusions (do NOT test, per Analysis): 1.5.2 open gap, out-of-range assignment `x[99L] <- 5` is silently ignored (1.5.2 Discovered, Q3); `[` on `NULL` base returns `Null` (vm.rs:402). Neither is in the nine required tests.
- Test names must start with `index_` or `assign_`, matching the required prefixes. Existing helpers `eval`, `eval_err`, `assert_val` are reused.
- Risk: `c(1L, -2L)` relies on unary minus over Int literal staying Int/materializable; if it parses to Dbl, `materialize_int` still works, so no change expected. If the parser rejects `-2L` inside `c()`, STOP and report.
